# Architecture

## Overview

The app runs locally. Streamlit handles interaction, PyPDF extracts page text,
Ollama creates embeddings and answers questions, and ChromaDB persists vectors
and metadata under `chroma_db/`.

```text
Upload PDF
  -> validate extension/size
  -> PyPDF page extraction
  -> page-aware text chunks
  -> Ollama nomic-embed-text
  -> persistent ChromaDB

Question
  -> question embedding
  -> cosine similarity retrieval
  -> distance threshold and result limit
  -> Ollama llama3.2:3b with retrieved context
  -> answer, retrieved source pages, supporting passages
```

## Modules

| Module | Responsibility |
| --- | --- |
| `app.py` | Streamlit interface, service/model status, uploads, index/remove, questions |
| `app_services.py` | Construct shared services and check Ollama model availability |
| `document_loader.py` | Validate and extract readable PDF pages with PyPDF |
| `chunker.py` | Split each page into chunks with source/page metadata |
| `embeddings.py` | Request real vectors from Ollama; errors do not trigger fake vectors |
| `vector_store.py` | Chroma persistence, metadata, searching, duplicate IDs, deletion |
| `retriever.py` | Embed question, query Chroma, filter by cosine distance |
| `llm_service.py` | Grounded prompt and local chat-model call |
| `rag_service.py` | Coordinate retrieval and answer/refusal behavior |
| `evaluate.py`, `evaluation.py` | Run the question set and calculate reported metrics |

## Storage and metadata

The Chroma collection is named `college_documents`, uses cosine distance, and
stores a chunk's text with its source filename, 1-based page number, chunk
index, and document ID. A document ID is the SHA-256 of the complete PDF bytes.
Re-uploading identical bytes is skipped by the UI; Chroma upserts also use
deterministic per-chunk IDs. Removing a document deletes all chunks matching its
document ID. Chroma persists across app restarts.

Do not manually edit Chroma files while the application is open. Re-embedding
with a model that changes vector dimensions requires intentionally rebuilding a
consistent local index; the app surfaces rather than hides dimension errors.

## Grounding and limitations

The prompt instructs the local model to use only supplied context and return the
exact configured refusal when context is insufficient. Retrieval also drops
passages whose cosine distance exceeds the configured threshold. Retrieved
source metadata is rendered from Chroma, not generated by the LLM.

Prompting and similarity filtering are not a formal proof that every generated
sentence is entailed by evidence. Users must verify important answers in the
displayed passages and original PDF. OCR, cloud fallback, authentication, and
remote Jira integration are not implemented.
